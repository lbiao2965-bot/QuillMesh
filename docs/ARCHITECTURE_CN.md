# QuillMesh 架构

## 技术栈

- Electron 34
- TypeScript 5
- Vite / electron-vite
- Milkdown 7 + ProseMirror
- KaTeX
- `docx`

## 进程边界

QuillMesh 保持 Electron 的主进程—预加载—渲染进程边界：

- `src/main/`：拥有文件系统权限，管理文档会话、文件监视、保存冲突、资源文件与原生导出。
- `src/preload/`：只暴露明确的类型化 IPC API，不将 Node.js 直接交给页面。
- `src/renderer/`：管理编辑器状态、标签、面板、命令、主题与交互控件。

## 文档会话

每个已打开文档在主进程中拥有独立 `documentId`、规范化路径、磁盘修订、编辑版本和文件监视器。渲染进程不使用单一的全局“当前路径”，避免多标签之间串写。

保存会携带载入时的磁盘修订。如果目标文件已被外部改变，主进程拒绝普通保存并返回冲突；只有用户在对话框中明确选择“保留我的版本”后，才授权对同一目标强制保存。

## 编辑器状态

Milkdown/ProseMirror 是所见即所得模式的编辑核心。每个标签保存 Markdown 快照、脏状态、选择与滚动信息，源码双栏使用同一份 Markdown 会话数据同步。

标题折叠、代码换行等属于演示状态，不会改写 Markdown。导出时会克隆一份去除编辑控件的完整 DOM，保证被折叠的正文仍然进入导出结果。

## 资源安全

剪贴板图片仅能写入当前已保存文档旁的受管目录。主进程校验规范化路径和目录边界，并使用排他式文件创建减少同名覆盖。

## 兼容键

部分内部 CSS 类名、DOM 事件名及本地存储键仍使用 `colamd-*`。它们是从旧版迁移设置和自定义主题的兼容层，不是对外产品品牌。
